# اجرای مستقل و مرز آمادگی عملیاتی

هر مدرسه باید دامنه، تنظیمات، پوشهٔ داده و پشتیبان جدا داشته باشد. فایل داده
را در پوشهٔ عمومی وب، مخزن Git، همگام‌سازی عمومی یا GitHub Pages قرار ندهید.

## راه‌اندازی میزبان

`server.py` سرور توسعهٔ محلی است. برای اینترنت باید یک میزبان Python/WSGI
پشت HTTPS انتخاب و آزمایش شود. `wsgi.py` به دامنهٔ دقیق نیاز دارد؛ wildcard
مجاز نیست. برای نخستین اجرا `SCHOOL_SETUP_TOKEN` تصادفی لازم است. این مقدار
را در مخزن یا خط فرمان عمومی ننویسید؛ از مدیریت اسرار میزبان استفاده کنید.

| متغیر | کاربرد |
|---|---|
| `SCHOOL_ALLOWED_HOSTS` | دامنهٔ دقیق همان نصب، جداشده با ویرگول در صورت نیاز |
| `SCHOOL_DATA_DIR` | مسیر خصوصی و پایدار دادهٔ همان مدرسه |
| `SCHOOL_SETUP_TOKEN` | محافظ ساخت نخستین ادمین |
| `SCHOOL_SECURE_COOKIES` | مقدار پیش‌فرض ۱؛ کوکی امن برای HTTPS |

حذف یا تضعیف TLS و کوکی امن راه حل خطای ورود نیست. پیکربندی پراکسی مورد
اعتماد، IP واقعی برای محدودسازی ورود و زنجیرهٔ هدرهای forwarded باید روی
میزبان انتخاب‌شده آزموده شود. پذیرش هدر ارسالی هر کلاینت ممنوع است.

`/health/live` وضعیت اجرای برنامه و `/health/ready` دسترسی و نسخهٔ داده را
بدون افشای اشخاص و مبالغ گزارش می‌کنند. شناسهٔ درخواست در پاسخ و خطای داخلی
قرار می‌گیرد؛ بدنهٔ درخواست، گذرواژه، کوکی و کد دعوت لاگ نمی‌شوند.

## پشتیبان و مهاجرت

پشتیبان با API خود SQLite ساخته می‌شود؛ کپی زندهٔ تنها فایل اصلی در حالت WAL
جای این روش را نمی‌گیرد. مهاجرت از نسخهٔ سه به چهار افزودنی است و پیش از
تغییر، یک پشتیبان خصوصی `pre-v4` می‌سازد. نسخهٔ دادهٔ ناشناخته بازنویسی نمی‌شود.

برای بازیابی، برنامه را متوقف کنید، نسخهٔ فعلی را جدا نگه دارید و فایل
پشتیبان را ابتدا در یک پوشهٔ تازه و محیط جدا با نام `school.sqlite3` راه‌اندازی
کنید. integrity، روابط، ورود تازه و چند مانده را بررسی کنید؛ نشست‌های قبلی
پیش از بازگشت به سرویس واقعی باطل شوند. برنامهٔ رمزنگاری، نگهداری و پشتیبان
خارج از میزبان باید متناسب با مدرسه تعیین شود؛ دکمهٔ دانلود به‌تنهایی این سیاست نیست.

## انتشار و بازگشت

پیش از انتشار: نصب وابستگی با lockfile، کنترل‌ها، ساخت تازه، حذف خروجی آزمون
رابط، پشتیبان و بررسی اسرار. پوشهٔ `web` باید خروجی `pnpm build` باشد و فایل
`qa-*` نداشته باشد. هیچ کاربر یا پایگاه دادهٔ آزمون همراه کد منتقل نمی‌شود.

بازگشت کد بعد از مهاجرت داده باید همراه نسخهٔ سازگار پایگاه داده و برنامهٔ
بازیابیِ آزموده باشد؛ برگرداندن فایل Python به‌تنهایی rollback داده نیست.
امنیت مستقل، بار هم‌زمان، Android واقعی، Windows واقعی و استقرار HTTPS در
این مرحله تأیید عملیاتی ندارند. پیش از دادهٔ واقعی مدرسه این کنترل‌ها باز هستند.
