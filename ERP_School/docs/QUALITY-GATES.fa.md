# نقش‌های بازبینی و شرط پذیرش هر فیچر

این نقش‌ها چارچوب بازبینی تخصصیِ توسعه با کمک دستیارند؛ وجود این سند به معنی
تشکیل تیم انسانی یا تأیید مستقل متخصصان نیست. بازبینیِ انجام‌نشده «باز» می‌ماند.
شروع بررسی UI، UX و عملیات برخی ایرادهای پایه را مشخص کرد؛ همهٔ نقش‌ها بازبینی
مستقل نهایی ارائه نکرده‌اند. آزمون‌های اجراشده جدا از این تأییدها گزارش می‌شوند.

| نقش | خروجی لازم پیش از پذیرش |
|---|---|
| UX | مسیر روشن هر نقش، حالت خالی، بارگذاری، خطا و موفقیت؛ پیش‌نمایش و تأیید عملیات سال؛ انتخاب صریح طرف مالی |
| UI | فونت واقعی، راست‌به‌چپ، سه اندازه، پنج تم، کنترل لمسی حداقل ۴۴ پیکسل، فوکوس و جدول با پیمایش محلی |
| DBA | طرح و کلیدها، ایندکس، تراکنش اتمیک، کنترل تکرار و رقابت، مهاجرت و پشتیبان/بازیابی آزمایش‌شده |
| DevOps | نصب با نسخه‌های قفل‌شده، ساخت قابل تکرار، اسرار جدا، health/readiness، گزارش خطا، برنامهٔ انتشار و بازیابی |
| CTO | مرز ماژول و وابستگی، نام‌گذاری و سادگی، استقلال قواعد مالی، حفظ قرارداد، ریسک و بدهی فنی مستند |
| QA | سناریوی اصلی، ورودی نامعتبر و مرزی، نقش و محدوده، تکرار، قطع پاسخ، رقابت، rollback و ماندگاری |

## شرایط توقف انتشار عملیاتی

- نشت اطلاعات، ارتقای دسترسی، از دست رفتن یا تکرار طلب، سند نامتوازن، خرابی
  مهاجرت یا نداشتن مسیر بازیابی، مانع انتشار است.
- شبیه‌سازی اندازه در Chrome جای آزمون گوشی و تبلت فیزیکی را نمی‌گیرد.
- آزمون API واقعی با SQLite و بررسی رابط با API ساختگی دو نوع شاهد متفاوت‌اند؛
  هیچ‌کدام به نام آزمون انتها‌به‌انتهای ورود در مرورگر گزارش نمی‌شود.
- اگر ساخت و آزمون خودکار گذشت، هنوز بازبینی امنیت مستقل، پذیرش کاربر، آزمون
  بار واقعی، میزبان HTTPS و بازیابی عملیاتی لازم است. نسخهٔ توسعه خودکار به
  محیط واقعی مدرسه ارتقا نمی‌یابد.

## اصلاح‌های پایهٔ اعمال‌شده

خطا در فرم باقی می‌ماند و به اعلان چندثانیه‌ای محدود نیست. انتخاب نخستین
دانش‌آموز یا طلب به‌صورت ضمنی انجام نمی‌شود. درخواست مالی با پاسخ نامشخص با
همان کلید پیگیری می‌شود. گذرواژه در صف درخواست مرورگر ذخیره نمی‌شود. قالب
متن دکمهٔ رنگ دلخواه در آزمون کنتراست بررسی می‌شود. اطلاعات ورود و کوکی از
منطق هویت جدا شده‌اند و آزمون معماری این مرز را کنترل می‌کند.

## اجرای کنترل‌ها

```sh
pnpm check
```

شامل TypeScript سخت‌گیرانه، قراردادهای Python/SQLite، کنترل معماری و فونت‌ها،
آزمون منطق سمت مرورگر و ساخت رابط است. قالب آمادهٔ CI در `ci/` قرار دارد؛
تا زمان ثبت آن در مسیر فعال مخزن، اجرای GitHub Actions ادعا نمی‌شود.
